## 摘要
内容审核分类器通常被孤立地评估，但实际部署需要选择在何处干预以及标记后采取何种后续操作。我们使用两个端到端的客户结果指标而非组件准确率来评估这些选择：有用性（Usefulness，即显示无害且相关响应的轮次比例）和有害暴露（Harmful Exposure，即显示有害响应的轮次比例）。延迟和错误率作为诊断指标。我们在人工标注的产品基准和公开的ToxicChat评估集上，比较了仅输入、仅响应以及输入+响应硬阻断策略。在所评估的工作点下，仅响应策略在两种场景中均实现了最高的纯过滤有用性，而输入+响应策略实现了更低的有害暴露。将仅响应阻断替换为响应+重写，恢复了大部分被阻断的流量，并在选定配置下产生了与仅响应阻断相同的观测有害暴露计数；这种相等性并非等价结果。与LLM路由相比，探针路由在结果可比的情况下，大幅缩短了条件路由与生成时间。一项针对性的输出审查表明，重写通过泛化触发语言同时保留良性意图和安全重定向，在过滤通过率与有用性之间取得了平衡；然而，某些敏感领域的输出仍会遗漏潜在的安全相关信息。这些结果支持在特定部署的安全和延迟约束下比较审核配置，而非应用通用的过滤位置规则。代码及公开成果可在 https://github.com/microsoft/mod-frontier 获取

## Abstract
Content-moderation classifiers are usually evaluated in isolation, but deployment requires choosing where to intervene and what follows a flag. We evaluate these choices using two end-to-end customer-outcome metrics rather than component accuracy: Usefulness, the fraction of turns with a shown, non-harmful, relevant response, and Harmful Exposure, the fraction with a shown harmful response. Latency and error rates are diagnostics. We compare Input only, Response only, and Input + response hard blocking on a human-labelled product benchmark and public ToxicChat evaluation. At the evaluated operating points, Response only achieves the highest filter-only Usefulness in both settings, while Input + response achieves lower Harmful Exposure. Replacing Response only blocking with Response + rewrite recovers most blocked traffic and yields the same observed Harmful Exposure count as Response only blocking for the selected configuration; this equality is not an equivalence result. Probe routing substantially reduces conditional route-and-generation time relative to LLM routing at comparable measured outcomes. A focused output review shows how rewrites balance filter passage with usefulness by generalizing triggering language while retaining benign intent and safe redirection; some sensitive-domain outputs nevertheless omit potentially safety-relevant support information. These results support comparing moderation configurations under deployment-specific safety and latency constraints rather than applying a universal placement rule. Code and public artifacts are available at https://github.com/microsoft/mod-frontier

## 1. 核心问题与整体含义
- **研究动机**：传统内容审核分类器通常被孤立评估（仅看分类准确率），但在实际部署中，系统需要做出一系列顺序决策：在何处干预（输入端、输出端或双重干预）以及干预后采取何种动作（硬阻断还是重写恢复）。这些决策联合决定了系统的阻断流量、延迟、残余危害和过度阻断，而单一的组件准确率无法反映这些端到端的客户体验。
- **整体含义**：内容审核不应追求单一的“最佳位置”或通用规则，而应将其视为一个受约束的干预配置问题。系统应在满足特定部署的“有害暴露”上限和延迟约束下，最大化对话的“有用性”。

## 2. 提出的方法论
- **核心思想**：提出以端到端客户结果指标为核心的决策框架，将“干预位置”和“干预动作”作为实验变量，在受约束的安全条件下比较不同配置。
- **关键指标**：
  - **Usefulness（有用性）**：最终显示给用户且无害、相关的响应轮次占比（主优化目标）。
  - **Harmful Exposure（有害暴露）**：最终显示给用户且有害的响应轮次占比（主安全约束）。
  - **诊断指标**：端到端阻断率、端到端误报率（基于客户视角定义）、有害响应率、延迟。
- **干预位置配置**：
  - **Input only**：仅过滤用户输入，标记则阻断。
  - **Response only**：输入直达生成器，仅过滤模型输出，标记则阻断。
  - **Input + response**：双重过滤，任一标记则阻断。
- **干预动作配置**：
  - **Response + rewrite**：对被标记的输出不直接阻断，而是通过路由分类意图和领域，使用重写器生成安全且相关的回复，并再次过滤（仅一次重试，未过则阻断）。
- **关键技术细节**：
  - **路由机制**：比较了LLM路由与轻量级探针路由。探针读取Qwen3-4B第18层残差流，通过注意力池化架构预测意图（拒绝/重写）和领域（8个类别）。
  - **重写器与提示词优化**：重写器使用Qwen3-4B或GPT-5；提示词通过GEPA（反射式提示进化）算法针对特定过滤器进行优化，奖励函数结合了过滤器通过率、相关性和无害性。

## 6. 主要结论与发现
- **位置选择权衡**：Response only（仅过滤输出）在纯过滤配置中Usefulness最高，因为现代对齐模型本身已安全处理了大量有害输入，输入端过滤容易过度阻断；Input + response（双重过滤）的Harmful Exposure最低，但Usefulness牺牲最大。
- **重写恢复有效**：Response + rewrite策略恢复了大部分被阻断的流量（内部Usefulness从85.68%升至95.04%），且在选定配置下观测到的Harmful Exposure与Response only相同。
- **探针路由大幅降延迟**：与LLM路由相比，探针路由将条件路由与生成时间从13.8秒降至0.47秒（降低29倍），且结果可比。
- **重写的隐性代价**：定性审查发现，重写通过泛化触发词来通过过滤器，但这可能导致丢失具体的细节；在自残等敏感领域，重写可能遗漏原回复中包含的危机援助信息。

## 7. 优点
- **视角创新**：打破孤立评估分类器的传统，首次从端到端客户视角定义Usefulness和Harmful Exposure，更贴近实际部署需求。
- **系统性解耦**：将“在哪里干预”和“如何干预”解耦为可控变量，清晰刻画了安全与有用的帕累托前沿。
- **工程落地性强**：提出的探针路由+重写+重筛机制，在保证安全的前提下显著降低了延迟并恢复了流量，具有极高的工业界应用价值。
- **严谨的统计与声明**：对统计等价性、数据泄露（ToxicChat训练集）、指标定义（客户视角误报率）的讨论非常严谨，避免了过度解读。

## 8. 不足与局限
- **数据局限**：内部基准为人工编写的危害富集单轮英文数据，无法代表真实生产环境的流量分布和多轮对话场景。
- **系统泛化性未知**：结论可能不适用于智能体系统（输出过滤可能无法阻止已执行的副作用）、其他语言或非对齐模型。
- **评估偏差**：11组重写扫视依赖自动评分器（存在假阳性/阴性风险），虽核心结论有人工标注支撑，但自动评分器对有害/无关重写的敏感度未得到验证。
- **延迟测量不完整**：仅测量了条件重写阶段的组件延迟，未包含完整的用户可见端到端延迟（如流式缓冲、并发负载等），需在实际部署栈重新测量。
- **过滤器适配问题**：实验中输入和输出使用同一过滤器，但该类过滤器通常针对短文本优化，针对长文本输出的过滤效果可能不佳；更换过滤器需重写整个GEPA提示词包。

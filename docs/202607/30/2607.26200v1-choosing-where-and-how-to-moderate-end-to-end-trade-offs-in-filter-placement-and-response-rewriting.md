## 摘要
内容审核分类器通常被孤立评估，但实际部署需要选择在何处干预以及标记后采取何种后续操作。我们使用两个端到端的客户结果指标而非组件准确率来评估这些选择：有用性（Usefulness，即显示无害且相关响应的轮次比例）和有害暴露（Harmful Exposure，即显示有害响应的轮次比例）。延迟和错误率作为诊断指标。我们在人工标注的产品基准和公开的ToxicChat评估集上，比较了仅输入、仅响应以及输入+响应硬阻断策略。在所评估的工作点下，仅响应策略在两种场景中均实现了最高的纯过滤有用性，而输入+响应策略实现了更低的有害暴露。将仅响应阻断替换为响应+重写，恢复了大部分被阻断的流量，并在选定配置下产生了与仅响应阻断相同的观测有害暴露计数；这种相等性并非等效结果。与LLM路由相比，探针路由在结果可比的情况下，大幅缩短了条件路由与生成时间。一项针对性的输出审查表明，重写通过泛化触发语言同时保留良性意图和安全重定向，在过滤通过率与有用性之间取得了平衡；然而，某些敏感领域的输出仍会遗漏潜在的安全相关信息。这些结果支持在特定部署的安全和延迟约束下比较审核配置，而非应用通用的过滤位置规则。代码与公开数据集可在 https://github.com/microsoft/mod-frontier 获取

## Abstract
Content-moderation classifiers are usually evaluated in isolation, but deployment requires choosing where to intervene and what follows a flag. We evaluate these choices using two end-to-end customer-outcome metrics rather than component accuracy: Usefulness, the fraction of turns with a shown, non-harmful, relevant response, and Harmful Exposure, the fraction with a shown harmful response. Latency and error rates are diagnostics. We compare Input only, Response only, and Input + response hard blocking on a human-labelled product benchmark and public ToxicChat evaluation. At the evaluated operating points, Response only achieves the highest filter-only Usefulness in both settings, while Input + response achieves lower Harmful Exposure. Replacing Response only blocking with Response + rewrite recovers most blocked traffic and yields the same observed Harmful Exposure count as Response only blocking for the selected configuration; this equality is not an equivalence result. Probe routing substantially reduces conditional route-and-generation time relative to LLM routing at comparable measured outcomes. A focused output review shows how rewrites balance filter passage with usefulness by generalizing triggering language while retaining benign intent and safe redirection; some sensitive-domain outputs nevertheless omit potentially safety-relevant support information. These results support comparing moderation configurations under deployment-specific safety and latency constraints rather than applying a universal placement rule. Code and public artifacts are available at https://github.com/microsoft/mod-frontier

## 1. 核心问题与整体含义
* **核心问题**：传统内容审核分类器通常被孤立评估（仅看分类准确率），但在实际部署中，系统需要做出一系列顺序决策：在何处干预（输入端、输出端或双重干预）以及干预后采取何种动作（硬阻断还是重写恢复）。孤立评估无法反映这些决策对最终用户体验的联合影响。
* **整体含义**：内容审核不应仅追求组件级准确率，而应追求端到端的客户结果。不存在绝对通用的最佳过滤位置，部署团队必须在特定的安全容忍度（有害暴露上限）和延迟约束下，权衡不同配置的“有用性”与“安全性”。

## 2. 提出方法论
* **核心思想**：将审核配置（干预位置 + 干预动作）作为实验变量，使用端到端的客户结果指标而非组件准确率进行评估与决策。
* **干预位置**：对比三种硬阻断位置——仅输入、仅响应、输入+响应。
* **干预动作**：将硬阻断替换为“选择性重写”，即对被标记的响应进行安全重写，并再次过滤审查，若仍被标记则硬阻断（无二次重试）。
* **核心指标体系**：
  * **决策指标**：有用性（Usefulness，最终显示无害且相关响应的轮次比例，越高越好）；有害暴露（Harmful Exposure，最终显示有害响应的轮次比例，越低越好）。
  * **诊断指标**：端到端阻断率、端到端误报率（从客户视角，安全提示被硬阻断即算误报）、有害响应率、延迟。

## 6. 主要结论与发现
* **过滤位置权衡**：仅响应过滤在纯过滤配置中提供最高的有用性（因为现代对齐模型本身已能安全处理大部分有害输入，输入端过滤容易过度阻断）；输入+响应过滤提供最低的有害暴露（最安全但最保守）。
* **重写恢复流量**：将仅响应硬阻断替换为响应+重写，能恢复大部分被阻断的流量（内部有用性从85.68%升至95.04%），且在选定配置下观测到的有害暴露计数与仅响应硬阻断完全相同（注意：这不代表统计等效）。
* **探针路由降延迟**：与LLM路由相比，探针路由在结果可比的情况下，将条件路由+生成时间从13.8秒大幅降至0.47秒（29倍加速）。
* **重写的隐性代价**：定性审查发现，重写通过泛化触发词来通过过滤器，但在敏感领域（如自残）可能会丢失关键的安全支持信息（如危机热线），需在细节保留与安全间校准。

## 7. 优点
* **视角创新**：打破了孤立评估分类器的传统，首次从端到端客户结果的视角，将“位置”和“动作”作为联合优化的变量。
* **指标设计合理**：提出的有用性与有害暴露指标直接映射产品目标，特别是将E2E误报率定义为客户视角的阻断，更符合实际部署逻辑。
* **工程价值高**：探针路由+选择性重写的方案，在几乎不增加有害暴露的前提下，显著提升了系统可用性并大幅降低了推理延迟。
* **开源与可复现**：公开了探针权重、提示词包、评估代码及记录输出，支持社区在ToxicChat上复现核心发现。

## 8. 不足与局限
* **数据与分布局限**：内部基准为单轮、英文、危害富集数据，结论无法直接推广至多轮对话、Agentic系统或自然流量分布。
* **评估偏差风险**：大规模重写扫视依赖LLM自动评估器，虽然对选定配置进行了人工校验，但自动评估器对有害或无关重写的敏感度未知。
* **延迟测量不完整**：仅测量了条件重写阶段的组件延迟，未包含原始生成、缓冲、并发等完整用户可见延迟，无法直接用于线上延迟达标判断。
* **过滤器耦合**：实验使用单一过滤器，且输入/输出端使用同一过滤器（未针对文本长度特性适配），不同过滤器或阶段特异过滤器可能改变权衡前沿。
* **等效性缺失**：重写与硬阻断的有害暴露计数相同仅是观测结果，缺乏预设边界的统计等效性检验。

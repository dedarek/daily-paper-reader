## 摘要
我们提出了ARBITER，一种新颖的大语言模型（LLM）护栏框架，该框架引入了两个关键理念：（i）双假设推理，一种用于LLM护栏的推理方法，在做出安全决策之前，会显式考虑提示词的安全与不安全解释；（ii）多组件监督微调（MC-SFT），一种用于基于推理的护栏的结构化训练损失，它将LLM输出分解为逻辑组件，并根据其重要性进行加权。现有的基于推理的护栏通常依赖于昂贵的流程，例如使用更大或闭源的教师模型生成推理轨迹，以及应用全参数微调。相比之下，ARBITER采用了一种高性价比的自生成策略来生成推理轨迹，并采用基于LoRA的参数高效微调，同时仍能取得比这些昂贵方法更好的性能。此外，ARBITER为不安全决策提供了忠实的证据短语解释，从而实现了一种更透明、更具可解释性的护栏方法。在三个安全审核基准上的实验表明，ARBITER优于现有的基于推理和非推理的护栏基线，在域外评估中取得了明显的提升。

## Abstract
We propose ARBITER, a novel LLM guardrail framework that introduces two key ideas: (i) dual-hypothesis reasoning, a reasoning method for LLM guardrails that explicitly considers both safe and unsafe interpretations of a prompt before making a safety decision, and (ii) multi-component supervised fine-tuning (MC-SFT), a structured training loss for reasoning-based guardrails that decomposes LLM outputs into logical components and weights them according to their importance. Existing reasoning-based guardrails often rely on expensive procedures, such as generating reasoning traces using larger or closed-source teacher models and applying full-parameter fine-tuning. In contrast, ARBITER uses a cost-effective self-generation strategy for reasoning traces and LoRA-based parameter-efficient fine-tuning while still achieving better performance than these expensive approaches. Additionally, ARBITER provides faithful evidence-phrase explanations for unsafe decisions, enabling a more transparent and interpretable guardrail method. Experiments on three safety moderation benchmarks show that ARBITER outperforms existing reasoning-based and non-reasoning guardrail baselines, with clear gains in out-of-domain evaluations.

## 2. 提出的方法论
### 核心思想
提出 **ARBITER** 框架，包含两个互补创新：
1. **双假设推理**：在做出安全决策前，显式构建并对比提示词的“安全假设”与“不安全假设”。
2. **多组件监督微调（MC-SFT）**：将结构化输出分解为逻辑组件，按重要性加权计算损失。

### 关键技术细节与流程
- **自生成推理轨迹**：不依赖外部大模型，而是由待微调的基础模型（Llama-3.1-8B-Instruct）自身离线生成双假设推理轨迹。
- **推理生成流程（4步）**：
  1. **缓存前缀**：将指令与提示词输入模型，保存键值缓存（KV IP）。
  2. **生成安全假设**：附加引导词“Safe Hypothesis:”，生成安全解释文本。
  3. **生成不安全假设**：复用缓存，附加引导词“Unsafe Hypothesis:”，生成不安全解释文本（2和3可并行）。
  4. **生成审议**：将两假设随机排序拼接到前缀后，附加引导词“Deliberation:”，生成对比两者的审议文本。
- **推理与输出结构**：审议之后，模型输出“胜者”及最终的JSON结果（包含安全标签与证据短语解释）。

### 公式与算法说明
- **MC-SFT 损失函数**：
  - 公式：$L_{MC-SFT} = \lambda_r L_r + \lambda_w L_w + \lambda_y L_y + \lambda_e L_e + \lambda_{syn} L_{syn} + \lambda_a L_a$
  - 组件分解：$L_r$（推理假设与审议）、$L_w$（胜者Token）、$L_y$（最终安全标签）、$L_e$（解释短语）、$L_{syn}$（JSON语法）、$L_a$（辅助推理对齐损失）。
  - 权重分配：高优先级（$\lambda_y, \lambda_e = 1.0$），中优先级（$\lambda_w = 0.5$），低优先级（$\lambda_r, \lambda_{syn} = 0.1, \lambda_a = 0.2$）。
  - 掩码交叉熵：对每个组件应用特定的Token掩码计算交叉熵。
- **辅助推理对齐损失（$L_a$）**：
  - 包含假设-审议对齐（$L_{hyp-delib}$）和审议-解释对齐（$L_{delib-exp}$）。
  - 通过计算最后隐藏状态的余弦相似度，鼓励审议结果与真实标签对应的假设对齐；对于不安全提示，进一步鼓励审议与最终证据解释对齐。
